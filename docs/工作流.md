# 工作流（agent 提假设 → 机器裁决）

> 这份是从真实跑完 6 轮、1,816 份配置的实践里提炼的可复用编排。
> 每个"门"都是**机器裁决**，不依赖 agent 自述。

## 一、一轮的五步

```
① 给上下文   读出上一轮的实测结果 + 因子清单 + 形态要求，写进 prompt（agent 无记忆）
② 扇出写配置 8 个 agent × 34 份 = 272 份，每个 agent 一个独立子目录（避免写冲突）
③ 三道机器门 load_config → 形态门 → 结构去重门（任何一道不过就重写，不进回测）
④ 回测        run_batch 分块跑，结果进台账
⑤ 共同池终判  layers_robust.ps1 跑 L1~L8，产出下一轮的输入
```

## 二、提示词骨架（每轮照抄，只换"设计轴"）

```
你是量化研究员，写第 N 轮 score 型配置单。

## 事实（必须遵守）
- 池 1,545 只；搜索期 2014-01-01~2022-12-31；等权全池 +15.11%/年（真正的对手，不是沪深300）
- 形态必须是 score 型：holdings 30 / 周度换手 / neut_industry: true
- 可用零件：size_ln、pb、ps_ttm、pe_ttm、turn_ma_n(n)、vol_n(n)、ret_n(n)、roe、
  or_yoy、netprofit_yoy、tl_on_list、fc_chg_mid、ts_pct、ind_rank、xsec_pct、ulcer_n
- **每份至少一个带 n 的因子**，否则 L5 邻域为 0，会被判"空真通过"
- score 型里写 buy/sell/rank 会被静默忽略

## 上一轮实测（必须针对它写新假设，不要重复）
| 轮 | A 路 L2 | B 路 L2 | 年化中位 |
|...| 上一轮表格 |

## 你的方向
第 s 组：<一句具体的设计轴，例如"固定 size −1.5，只横扫 turn 窗口 20/60/120/250">

写 34 份到 strategies/{A|B}/roundN/，文件名 {a|b}_rN_s{slot}_<两位序号>_<语义名>.yaml
每份 desc 写清：选什么 → 为什么 A 股该有超额 → 与同组其它编号差在哪
```

**为什么要点名"等权全池 +15.11%"**：第一轮只写了"基准沪深300 +7.5%"，agent 以为自己跑赢了市场，
实际上全部跑输了"随便买一篮子"的朴素策略。

## 三、三道机器门

| 门 | 脚本 | 判据 | 本次实际拦下的问题 |
|---|---|---|---|
| 语法门 | `engine/config.py` | `load_config` 逐份加载 | 中文键、缺 `n`、阈值越档 |
| **形态门** | `tools/check_form.py` | score 占比 ≥ 80% | 第 1 轮 1.0%、第 2 轮 10.5% —— 若当初有这道门，能省 400 份配置 |
| 去重门 | `funnel.canonical_config` | 结构签名两两互异 | 5 对"同假设换参数"被标为近邻重复 |

```bash
python tools/check_form.py --round 6 --min-score 0.8   # exit 1 就打回，不要进回测
```

## 四、回测与漏斗的调度

```bash
# 分块进程：单进程内存按 ~100-150MB/份线性涨，gc 无效 → 每块换进程
python tools/farm_chunked.py --seeds 1-20 --count 600 --chunk 60 --workers 8

# 漏斗：multiprocessing.Pool 会死锁（worker 停在 queues.get，CPU 归零）
pwsh -File tools/layers_robust.ps1 -Workers 6
```

**并发按内存定，不按 CPU 定**：面板 3.76M 行，8 worker × 3.4GB ≈ 25GB 是 32GB 机器的上限。

**长任务要能活过会话**：用 WMI 创建进程（`Invoke-CimMethod Win32_Process Create`），
不要用 `Start-Process` 挂在自己的作业对象里；也不要用长 `Start-Sleep` 等，改为定时短查询。

## 四·五、这些门已经焊进代码（不只是文档）

第一版把纪律写在文档里，结果**跳过不报错、跑完才发现**（第 1~2 轮 200 份 rule 型配置白跑；
开封后又想重跑封存）。现在改成代码闸门：

| 门 | 焊在哪里 | 行为 |
|---|---|---|
| **形态门** | `engine/run_batch.py`（调 `engine/gates.py`） | 目录属于 `strategies/{A,B}/roundN` 且 score 占比 < 80% → **exit 3，直接拒绝回测**；确要绕过加 `--force-form`，输出里留痕 |
| **冻结门** | `tools/sealed_eval.py` | 没有 `reports/名单冻结.json`、或名单在冻结后被改过 → **拒绝开封** |
| **封存期写保护** | `tools/pipeline.py snapshot` / `audit` | 开封前对 `data/`、`strategies/`、`engine/` 拍快照；开封后核对，任何文件被改 → **exit 1** |
| **报告回源门** | `tools/verify_report.py` | 报告数字与 JSON/台账不一致 → **exit 1** |

```bash
python tools/pipeline.py status      # 一眼看四道门的状态
python tools/pipeline.py precheck    # 开封前全部前置条件，任一不满足 exit 1
python tools/pipeline.py freeze      # 冻结名单（写 SHA256）
python tools/pipeline.py snapshot    # 开封前拍快照
python tools/pipeline.py audit       # 开封后核对受保护目录有没有被改
```

实测：`strategies/A/round1`（100% rule）→ `exit 3 拒绝回测`；
`strategies/A/round3`（100% score）→ `exit 0 通过`；
把 `engine/gates.py` 的 mtime 改一下 → `audit` 立刻报「被修改」并 exit 1。

## 五、失败模式速查

| 症状 | 根因 | 处置 |
|---|---|---|
| 价格全对但策略全亏 | 形态错了（rule 型追涨） | 跑形态门，改 score 型 |
| 大批 `MemoryError`（几 MB 都分配不出） | 并发过高，每进程一份面板副本 | 降 worker 或分块 |
| 进程都在、CPU 0.0 秒、台账不动 | Pool 死锁（有 worker 非正常退出） | 盯台账 mtime，3 分钟不动就重启 |
| 台账行数远大于唯一配置数 | 看门狗重启后重跑 | 统计按 `(config,start,end)` 去重，DSR 的 N 按唯一配置 |
| 报告数字与产物对不上 | 改流程没改报告 | `tools/verify_report.py` 回源门 |
| 抓取被拉黑 | 同一 IP 并发过高 | 多出口 IP、每 IP 单会话 |
