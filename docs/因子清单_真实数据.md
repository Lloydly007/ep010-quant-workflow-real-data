## 口径修正（2026-10-24，跑完第 2 轮后追加）

**下面正文里凡是"打分型在本池退化"的结论，都是拿 30 只试点池推出来的，在本研究实际的 1,545 只池上不成立。以本节为准。**

- 本研究的池是 **1,545 只**（沪深300 ∪ 中证500 月末历史成分并集，2013-12~2024-12），不是 30 只。
- `holdings: 30` 在 1,545 只里只占 1.9%，**选股维度真实存在**，不存在"全池等权买入"的退化。
- 原项目 EP010 的 A 路 1,353 份配置里 **score 型 1,249 份（92%）**、B 路 1,398 份里 score 型 1,373 份（98%）；它唯一活过 L6 的三个候选**全部是 score 型**（周度打分、目标 30 只、`neut_industry: true`）。

### 本轮主力形态（写配置单请照这个）

优先级：**score 型 ≥ 80%，rule 型 ≤ 20%**。

score 型的骨架（原项目三席的形态）：

```yaml
type: score
factors:
- op: size_ln        # 小市值，负权
  weight: -1.25
- op: pb             # 低估值，负权
  weight: -0.5
- op: turn_ma_n      # 低换手，负权；必须带 n 才能产生 L5 邻居
  n: 120
  weight: -0.75
holdings: 30
rebalance: weekly_first_trade_day
neut_industry: true
```

可用打分零件（全部是真实字段）：`size_ln`、`pb`、`ps_ttm`、`pe_ttm`、`turn_ma_n`、`vol_n`、
`ret_n`、`close_over_ma_n`、`ts_pct`、`ind_rank`、`xsec_pct` 等。
**`roe` 等财务零件在本轮为空表，绝对不能引用**——原项目 a_r6_067/068 都带 ROE 权重，
本轮无法复现，报告须标注。

### 每条 score 配置的硬要求

1. 至少一个带 `n` 的因子（`turn_ma_n`/`vol_n`/`ret_n`/`ts_pct` 的 `of.n`），否则 L5 邻居为 0，会被判空真通过。
2. `holdings` 固定 30，`rebalance` 用 `weekly_first_trade_day` 或 `monthly_first_trade_day`。
3. 因子权重体现方向：小市值/低估值/低换手/低波 → 负权；动量/质量 → 正权。
4. 权重不要 20 份全一样，要让不同配置表达不同假设。

## 1. 可用因子家族表

### 1.1 A 路（趋势 / 动量 / 量价 + ETF 择时过滤）

| 家族 | 可用 op | 路 | 为什么可用（真实字段依赖） |
|---|---|---|---|
| A1 趋势与均线位置 | `ret_n` `ma_n` `close_over_ma_n` | A | 依赖 `adj_nav = daily.close × adj_factor`（81,220 行）。复权因子是全表派生值（后复权收盘÷不复权收盘，ffill+fillna(1.0)），99.4%≠1、最大 37.16，但与 `pct_chg` 自洽（price_check 0 偏差）。`ret_n`/`close_over_ma_n` 是比值，跨除权日口径一致；`ma_n` 输出是价位量级，见 2.4 不作条件。 |
| A2 相对高低点与突破 | `dist_high_n` `dist_low_n` `break_high_n` | A | 依赖 `daily.high/low × adj_factor` 与 `adj_nav`。`dist_high_n≤0`、`dist_low_n≥0`；`break_high_n` 取 0/1，前 N 根不含当日，不足 N 根为 NaN。 |
| A3 量能确认 | `vol_ratio_n` | A | 依赖 `daily.vol`（单位股）。只取“当日量 / 前 N 日均量（不含当日）”的比值，Tushare 列名的“手”与本地“股”差 100× 不影响结论。 |
| A4 连涨 / 日内结构 | `streak_up` `streak_down` `close_pos_range` | A | 依赖 `daily.pct_chg`（连涨阈值走 streak 整数档）；`close_pos_range` 依赖 `daily.high/low/close/pre_close`，均为不复权价（日内比例，符合 rules 第 2 章）。 |
| A5 市场状态（ETF 过滤） | `etf_above_ma_n` | A | 依赖 510300.SH 的 `fund_daily.close`（raw 11,566 行、4 只 ETF）在 N 日均线上方。`fund_adj` 恒 1.0，等于未复权收盘，除息日附近均线有小偏差，报告须注明。市场级，**只作 buy/sell 条件**。 |
| A6 分位 / 排名包装（A 基值） | `ts_pct` `xsec_pct` `ind_rank` | A | 依赖“活动基零件的列 + 逐码行窗 / 当日 30 只截面 / `l1_code` 分组”。`ts_pct` 必须同时给 `n` 与 `of`；`xsec_pct`、`ind_rank` 只给 `of`；基零件若死则整列 NaN。 |

|---|---|---|---|

### 1.3 计数口径

- 41 个注册 op = **25 可用 + 16 必死**；可用 25 = A 专属 11（10 个量价 + 1 个市场级 ETF）+ B 专属 11 + 共用包装 3（`ts_pct`/`xsec_pct`/`ind_rank` 在 A、B 各出现一次，去重后只算 3 个）。
- 可用 op 按阈值量纲：pct 9 个、mult 5 个、streak 2 个，合计 16 个可作条件；none 9 个只能 factors/rank；`etf_above_ma_n` 单独一类（市场级，只条件）。
- 指数成分与行业：`index_members` 106,399 raw 行（沪深300 39,900 + 中证500 66,499），去重 1,545/1,633 只；但日线只有 30 只，实际可交易面板就是这 30 只。`index_member_all` 只有 30 行当期快照。

## 2. 禁用清单

### 2.1 依赖空表的 16 个 op（整列 NaN 或恒 0）

9 个 `threshold_kind=none` 的死列连条件都写不进去（config 直接拒）；7 个有量纲的死列**语法能过、回测 0 笔**，是最危险的一类。

| 失效 op | 依赖空表（raw 行数） | 能否作 buy/sell | 现实现象 |
|---|---|---|---|
| `roe` `or_yoy` `netprofit_yoy` | `fina_indicator`（0 行） | 否（none） | 整列 NaN；作因子为常数 0.5 |
| `fc_type_code` `fc_chg_mid` `fc_days` | `forecast`（0 行） | 否（none） | 整列 NaN |
| `ind_median_fc_chg_mid` | `forecast`（0 行） | 否（none） | 整列 NaN |
| `ex_yoy` `ex_days` | `express`（0 行） | 否（none） | 整列 NaN |
| `inst_netbuy` | `top_list` + `top_inst`（各 0 行） | 是（pct） | 整列 NaN → 条件恒 False，2014–2022 实测 0 笔 |
| `margin_ratio` `margin_chg_n` | `margin_detail`（0 行） | 是（pct） | 同上，0 笔 |
| `hk_ratio` `hk_chg_n` | `hk_hold`（0 行） | 是（pct） | 同上，0 笔 |
| `fc_demean_ind` | `forecast`（0 行） | 是（pct） | 同上，0 笔 |
| `top_list_n` | `top_list`（0 行） | 是（mult） | 恒 0（不是 NaN）：`above 0.5` → 0 笔；`below 0.5` → 恒成立（等于没有条件） |

计数：9 个 none + 7 个有量纲 = 16。另有 `moneyflow_hsgt` 也是 0 行，但引擎从不读它（19 张表名单之外的第 20 个文件），不计入 op。

### 2.2 市场级算子 `etf_above_ma_n` 的三处硬禁令

- **作打分因子**：`engine/config.py` 抛 `零件 etf_above_ma_n 是市场级零件（当日全市场同值），不能作打分因子 / 排序键 / 嵌套基零件；只能作 buy/sell 条件（rules.md 7.5）`。
- **作排序键**（`rank`）：同上，`_reject_market_level(base, "rank")`。
- **作嵌套基零件**（`of` 里）：递归检查 `spec["of"]`，同样抛错。
- 另两道闸：`engine/funnel.py` 的 `MARKET_LEVEL_OPS` + `FACTOR_BASE_POOL` 把它从随机因子里剔除；`engine/backtest.py` 拒绝它在股票面板上求值（必须走 ETF 日线 `_etf_value_on`）。
- 后果：一旦混进因子，截面秩恒并列 0.5，选股退化为按代码序取前 N（v1 的 `m43_028` 先例）。**唯一合法位置：buy/sell 条件，取 `above 0.5`（在均线上方）或 `below 0.5`（在均线下方，反向假设须写明）。**

### 2.3 “看起来能用、实际 0 成交”的写法（7 个死条件 + 结构性 0）

| 写法（YAML 片段） | 引擎行为 | 实测后果 |
|---|---|---|
| `buy: {op: hk_ratio, dir: above, threshold: 5}` | `load_config` 通过 | 2014–2022 **0 笔成交**（NaN 条件恒 False）；对照 `ret_n` 配置 1,680 笔 |
| `buy: {op: margin_ratio, dir: above, threshold: 3}` / `margin_chg_n` / `inst_netbuy` / `fc_demean_ind` / `hk_chg_n` | 通过 | 同上，0 笔 |
| `buy: {op: top_list_n, n: 20, dir: above, threshold: 0.5}` | 通过 | 恒 0 → **0 笔** |
| `buy: {op: top_list_n, n: 20, dir: below, threshold: 0.5}` | 通过 | 恒成立 → 每天都满足，**等于没有买入条件** |
| `sell: {op: top_list_n, n: 20, dir: below, threshold: 0.5}` | 通过 | 卖出条件恒成立（等价于强制清仓/极高换手），看起来有卖出规则，实际是每天全卖 |
| `sell: {op: hk_ratio, dir: below, threshold: 1}` | 通过 | 永不触发；卖出退化为 `max_hold_days`/`stop_loss`（**规则形同虚设**） |
| `buy: {op: dist_high_n, n: 120, dir: above, threshold: 10}` | 通过 | `dist_high_n≤0`，`above +10` **结构恒不成立 → 0 笔**；正确写法是 `above -10`（距高点 10% 以内） |
| `buy: {op: dist_low_n, n: 20, dir: below, threshold: -5}` | 通过 | `dist_low_n≥0`，`below -5` **恒不成立 → 0 笔**；正确写法 `below 2`（距低点 2% 以内） |
| `buy: {op: close_pos_range, dir: above, threshold: 1.0}`（1.2/1.5/2.0 同） | 通过 | 取值 0~1，**阈值 >1 结构恒不成立 → 0 笔** |
| `buy: {op: break_high_n, n: 20, dir: above, threshold: 1.0}`（1.2/1.5/2.0 同） | 通过 | 取值 0/1，**恒不成立 → 0 笔** |
| `buy: {op: etf_above_ma_n, n: 60, dir: above, threshold: 1.0}` | 通过 | 同上，0 笔；只认 `above 0.5` / `below 0.5` |
| `{op: ts_pct, n: 20, of: {op: roe}}`（或 `xsec_pct`/`ind_rank` 套死列） | 通过 | 基列 NaN → 包装整列 NaN → 因子常数、条件恒 False |

> 说明：`OPS_CONDITION` 按注册表派生（23 个有量纲 op 全在里面），所以随机组会抽到上述死条件并产生 0 笔台账行（抽中率不低）。这是数据缺口的必然后果，**按 rules 如实记账、计入 N，不许手工剔除，也不许改生成器让随机组“好看”**。

### 2.4 “不会 0 成交、但选股失效”的写法

| 写法 | 为什么失效 | 处置 |
|---|---|---|
| 死列作打分因子（如 `factors: [{op: hk_ratio, weight: 0.4}, {op: ret_n, n: 60, weight: 0.6}]`） | 全 NaN 经 `_cross_rank` 映射为常数 0.5，无截面离散度；若全部因子都如此，分数全并列 → **按代码序取前 N**（v1 `m43_028` 先例），不 0 成交但等于没选股 | 整列剔除；不用死列凑因子数 |
| 死列作 `rank` 排序键 | 全部并列，等于不排序 | 同上 |
| `factors`/`rank`/`of` 里出现 `etf_above_ma_n` | config 三处直接抛错 | 只放 buy/sell |
| ~~打分型 `holdings: 30` + 30 只池~~ | 已作废：真实池 1,545 只，30 只 = 1.9%，不构成退化；原项目 A/B 两路 92%~98% 都是 score 型 | **score 型是本轮主力形态**（≥80%） |
| `buy: {op: ma_n, n: 20, dir: above, threshold: 10}` | 输出是价位（元），阈值却按 pct 档校验 → 实为“股价 > 10 元”筛选，与均线信号无关 | 只作 rank/factor；或包 `xsec_pct` 后作因子（包装不能作条件） |
| `close_over_ma_n` / `vol_ratio_n` 用 `above 0.5` | 比值型在 0.5 附近实质恒真（需腰斩才不满足），不构成过滤 | 用 1.0/1.2/1.5/2.0 等有经济含义的档 |
| `close_over_ma_n` 用 `below 0.5` | 需“跌破均线一半”，实质恒假 → 0 笔 | 改 `below 1.0` |

### 2.5 禁用写法清单（可直接对照）

1. 16 个空表 op 一律不写进配置：`roe` `or_yoy` `netprofit_yoy` `fc_type_code` `fc_chg_mid` `fc_days` `ex_yoy` `ex_days` `ind_median_fc_chg_mid` `inst_netbuy` `margin_ratio` `margin_chg_n` `hk_ratio` `hk_chg_n` `fc_demean_ind` `top_list_n`。

## 3. 两路分工

### 3.1 A 路 = 趋势 / 动量 / 量价（含 ETF 择时作为过滤条件）

- **条件池（buy/sell）**：`ret_n` `ma_n`（不建议）`close_over_ma_n` `dist_high_n` `dist_low_n` `vol_ratio_n` `streak_up` `streak_down` `close_pos_range` `break_high_n`，外加唯一市场级 `etf_above_ma_n`。
- **排序/因子池**：上述全部 + `ts_pct`/`xsec_pct`/`ind_rank`（基值取 A 路列）。`ma_n` 作因子只是“价位水平”代理，趋势含义弱，优先用 `close_over_ma_n`/`ret_n`。
- **典型形态**：rule 型，buy = 1～4 条趋势/量价条件（可加 1 条 ETF 过滤），`rank` 用动量/量比/波动排序，sell = 趋势破位，`max_hold_days` 3～60、`stop_loss` 5/8/10。示例见 4.6。
- **ETF 的正确用法**：只作“市场开关”条件（`above 0.5` 才买个股，`below 0.5` 作防守/反向假设），**不作为个股排序或因子**；组合层底仓的 200 日择时（rules 5.5）是另一套逻辑，不在配置单里实现。

### 3.2 B 路 = 估值 / 规模 / 换手 / 低波

- **条件池（buy/sell，只能是有 pct 量纲的这 5 个）**：`turn` `turn_ma_n` `vol_n` `atr_close_n` `ulcer_n`。
- **排序/因子池（none，只能 factors/rank）**：`pe_ttm` `pb` `ps_ttm` `size_ln` `ind_median_pb` `ind_median_ps`，外加包装。
- **结论：B 路在本数据上无法写“纯估值选股”**——`pe_ttm/pb/ps_ttm/size_ln` 作不了 buy/sell 条件（`threshold_kind=none`，config 直接拒）。可执行形态只有两种：
  1. **rule + rank（推荐）**：buy 条件用换手/低波/回撤（例：`turn_ma_n below 3` 或 `vol_n below 3` 或 `ulcer_n below 5`），`rank` 用 `{op: pb, order: asc}` / `{op: ps_ttm, order: asc}` / `{op: size_ln, order: asc}` 在合格集里挑 10 只。这样入选集合由换手/波动决定，估值只决定排序，报告必须写明这一点。
  2. **score 型（本轮主力，≥80% 的配置）**：factors 写估值/规模/换手/低波/动量，`holdings: 30` + 周度换手 + `neut_industry: true`；在 1,545 只池上这是真实选股，不是风格诊断。
- **估值排序陷阱**：`pe_ttm` 有 10.2% 负值，`order: asc` 会把亏损股排最前；`pb`/`ps_ttm` 全正，优先用它们做低估值排序。

### 3.3 覆盖率不完整（必须写进报告）

| 量价 | **完整** | 10 个（`ret_n`…`close_pos_range`） | 30 只、2013-01 起；复权因子派生但自洽 |

| 规模 | **部分** | `size_ln` | `circ_mv` 反推，无 `total_mv` |

### 3.4 池与口径对结论的硬限制

- **30 只、沪市主板、风格单一**（银行/钢铁/电力/航空/地产）；中证1000 未纳入（MANIFEST 明写），与 rules 7.5 三指数并集不符 → 小盘与流动性维度整体缺失。
- **ST 过滤静默失效**：`stock_basic.name` 全为空串、`namechange` 0 行 → `is_st` 恒 0，`backtest.py` 的 ST 剔除（808/901）不生效。所有结果须标注“ST 未剔除”，不得声称满足 rules 第 2 章。
- **涨跌停是派生值**：`stk_limit = pre_close×1.10/0.90`，未区分创业板/科创板 20%、ST 5%、北交所 30%。主板新股首日无涨跌幅限制，实测 600023（2013-12-19，+60.58%）、600025（2017-12-15，+43.78%）、600032（2021-05-25，+43.87%）被误判“涨停不能买”。本池不涉及 20% 板块，但结论不可外推。
- **停牌只覆盖 raw**：`suspend_d` 813 行、sealed 0 行，搜索期可用，封存期停牌不可判。
- **复权是派生的**：`adj_factor` 由后复权/不复权派生；`fund_adj` 恒 1.0 → ETF 未复权，ETF 均线在除息日附近有偏差。
- **单位**：`daily.vol` 是股、`amount` 是元（`amount/close/vol` 中位数 0.9998），列名却沿用 Tushare 的“手/千元”，差 100×/1000×。量比/换手用相对值不受影响；14.2 容量估计用 `amount` 时按元。
- **成分权重是伪造的**：`index_members.weight = 100/成分数`（等权），只能取成分集合，不能做加权基准或权重研究；去重池 1,545/1,633 只与文档 1,698 只不一致。
- **行业是单期快照**：`index_member_all` 只有 30 行、`in_date` 硬编码 20130101、`out_date` 空、600005 退市后为空。把当期行业回填全历史 = 前视污染，行业内排名/行业中性化只能作近似，报告须标注。
- **ts_code 两套命名**：股票/成分表是 `sh.600000`，ETF/基金是 `510300.SH`。股票表内部一致，ETF 常量与 `fund_daily` 能对上；跨表 join 不要混用两套格式。
- **封存越界**：`sealed/fund_daily`、`sealed/fund_adj` 到 20261023，`sealed/trade_cal` 到 20261231，越过研究截止日 2026-09-30，开封前必须截到 20260930。
- **9 个空文件**：8 张表 + 引擎不读的 `moneyflow_hsgt`；MANIFEST 对派生表也标 `"real": true`，只有 notes 文字披露，引用数据时必须自己核对真值性。

### 3.5 与八层 / 台账的接口

- **L1 口径**：规则型交易 ≥100 笔（买卖各算一笔）；打分型周度 ≥300 期、月度 ≥80 期（搜索期，引擎按频率分档，月度 299 期仍按月度档 ≥80 判）。
- **L5 邻域**：每份基础配置至少要有一个可移动参数。rule 型的 `max_hold_days` 与 `stop_loss` 必然产生邻居（4.6 示例实测 24 个）；score 型若因子全是无窗零件（`pb`/`turn`/`size_ln`）→ **0 邻居 → 空真通过**（实测：`pb`+`turn` 两份无窗因子的打分配置邻居数为 0），必须至少放一个带 `n` 的因子，或 `xsec_pct` 的 `of.n`（funnel 的 P8 补丁会枚举嵌套窗口）。
- **`--formal`**：正式漏斗是 `python engine/funnel.py layers --formal --workers N`；不带 `--formal` 只跑每组入围分前 30（`TRIAL_L5_TOP_K=30`），不能当正式结果。
- **N 口径**：台账行数（含探针、重试、失败），不是提交数或文件夹数；A/B 各 ≥6 轮 ×100～150 个基础配置。
- **命名**：A/B 路用 `a_`/`b_` 前缀 + 轮次；主随机 `m43_`（seed 43），副随机 `m1_`～`m20_`（seed 1～20）；邻域探针名必须含 `__`，正常回测、计入 N，但不参与 L5～L8 与入围排名。
- **去重**：与台账已有配置做规范化去重，忽略 `name`/`desc`，重复则重新采样。
- **角色**：`run_batch.py` 默认 `--role search`，区间触及 2023-01-01 抛 `RoleViolation`；但 `funnel`/`portfolio` 是进程内直调，不经过这道闸——验证期隔离靠纪律：配置单、命名、desc、笔记、迭代理由都不许引用 2023+。

## 4. 写配置单的语法要点

### 4.1 文件骨架

```yaml
name: a_r1_breakout_ma20    # 必填，唯一；邻域探针才带 __
type: rule                  # rule | score（必填）
desc: 一句话假设            # 可选，不参与规范化去重
```

可选 `industry_cap`：`0`（缺省=不启用）或 3/5/10/20/60/120/250，含义是“同一行业最多持有 N 只”。本池只有 15 个行业组（证监会门类）、最大一组 6 只，取 10 及以上恒不起作用；它只是持仓数量约束，**不做行业中性化**，不能拿它冒充 rules 7.5 的行业内排名。

### 4.2 条件（只用于 rule 的 buy/sell）

- **键固定英文**：`op`、`n?`、`of?`、`dir`、`threshold`。写中文 `方向`/`阈值` 会报 `dir 必须是 above/below，得到 None`。
- **比较语义**：`dir: above` = 零件值 **>** 阈值；`dir: below` = **<** 阈值（严格不等）。
- **buy 必须是非空列表；sell 可为空；多条条件为 AND。**
- **阈值量纲表**：

| 量纲 | 可用 op | 允许阈值 |
|---|---|---|
| pct（百分比档，可带负号） | `ret_n` `ma_n` `dist_high_n` `dist_low_n` `turn` `turn_ma_n` `vol_n` `atr_close_n` `ulcer_n` | ±1 / 2 / 3 / 5 / 8 / 10 / 15 |
| mult（倍数档，不可负） | `close_over_ma_n` `vol_ratio_n` `break_high_n` `close_pos_range` `etf_above_ma_n` | 0.5 / 0.8 / 1.0 / 1.2 / 1.5 / 2.0 |
| streak（整数档） | `streak_up` `streak_down` | 3 / 5 / 10 / 20 / 60 / 120 / 250 |
| none（**不能作条件**） | `pe_ttm` `pb` `ps_ttm` `size_ln` `ind_median_pb` `ind_median_ps` `ts_pct` `xsec_pct` `ind_rank` + 9 个死列 | — |

- **窗口 `n`**：只能 3/5/10/20/60/120/250；带窗零件必须给，无窗零件给了报错。
- **符号惯例**：`dist_high_n` 值 ≤0，“距高点 10% 以内”写 `above -10`；`dist_low_n` 值 ≥0，“距低点 2% 以内”写 `below 2`；`ret_n` “跌超 5%”写 `below -5`。
- **0/1 型**（`break_high_n`、`etf_above_ma_n`）只认 `above 0.5`；`below 0.5` 是补集（须写明反向假设）；`above 1.0+` 恒不成立。
- **阈值不能为 0**（pct 档从 1 起）。

### 4.3 rank（规则型可选）

```yaml
rank: {op: ret_n, n: 5, order: desc}     # 候选多于空余仓位时按 5 日涨幅降序取前 10
rank: {op: pb, order: asc}               # 低 PB 优先（无窗口零件不带 n）
```

- 只接受 `op` `n?` `of?` `order`；**不能带 `dir`/`threshold`**；`order` 只能 `asc`/`desc`（缺省 `desc`）。
- 市场级零件不能作 rank；排序键必须是活列（NaN 的排序位置不可依赖，会缺值的列不要拿来排序）。
- `rank` 对全部候选排序，但只有候选数超过空余仓位（10 − 持仓 − 挂起买单）时才改变入选结果；没有 rank 时按代码序取。
- 估值排序：`pe_ttm` 的负值会排最前，优先用 `pb`/`ps_ttm`。

### 4.4 factors（打分型专用）

```yaml
factors:
  - {op: xsec_pct, of: {op: ret_n, n: 20}, weight: 0.5}   # 20日动量的截面分位
  - {op: size_ln, weight: -0.3}                            # 小市值倾斜（负权）
holdings: 30
rebalance: monthly_first_trade_day
neut_industry: false
neut_size: true
```

- `factors` 非空；每项 `{op, n?, of?, weight}`；`weight≠0`，正=越大越买，负=反向；权重不是 rules 档位参数（绝对值任意，引擎按 |w| 归一）。
- `holdings` 固定 30；`rebalance` 二选一：`weekly_first_trade_day`、`monthly_first_trade_day`；`neut_industry`/`neut_size` 取 `true`/`false`（默认 false），实际生效项会写进 `summary.json` 的 `neutralization`。
- 打分型里写 `buy`/`sell`/`rank`/`max_hold_days`/`stop_loss` 会被**静默忽略**（不报错），别指望它生效。
- ~~本池 30 只 + holdings 30 = 全池买入~~ → 已作废：真实池 1,545 只，`holdings: 30` 是正常选股规模（见顶部「口径修正」）。

### 4.5 包装（`ts_pct` / `xsec_pct` / `ind_rank`）

```yaml
{op: ts_pct,  n: 20, of: {op: ret_n, n: 5}}    # 必须同时给 n 和 of
{op: xsec_pct, of: {op: pb}}                   # 只给 of，给 n 报错
{op: ind_rank, of: {op: ps_ttm}}               # 只给 of
```

- 输出 0~1；`threshold_kind=none` → **只能 factors/rank，不能作 buy/sell**（想要“分位 > 0.8”只能写成排序键或因子）。
- 基零件必须是活列；基死则整列 NaN。
- `config` 允许复合（如 `ts_pct of xsec_pct of pb`），但 `funnel` 生成器只包一层，且 `FACTOR_BASE_POOL` 已把三个 wrapper 从“基零件池”剔除（不会生成 wrapper 套 wrapper）；手工嵌套要自己确认 NaN 与窗口语义。

### 4.6 完整示例（14 行，已实跑通过）

```yaml
name: a_r1_breakout_ma20
type: rule
desc: 20日突破+量比确认，300ETF在60日线上方才买，持有10日止损8%
buy:
  - {op: break_high_n, n: 20, dir: above, threshold: 0.5}
  - {op: close_over_ma_n, n: 20, dir: above, threshold: 1.0}
  - {op: vol_ratio_n, n: 5, dir: above, threshold: 1.5}
  - {op: etf_above_ma_n, n: 60, dir: above, threshold: 0.5}
rank: {op: ret_n, n: 5, order: desc}
sell:
  - {op: close_over_ma_n, n: 20, dir: below, threshold: 1.0}
max_hold_days: 10
stop_loss: 8%
max_positions: 10
```

实跑校验：`python engine/config.py <file>` → `OK a_r1_breakout_ma20 rule`；`build_neighbor_set` → **24 个邻居**（buy 4 条 + sell 1 条的 n 与 threshold、rank 的 n、`max_hold_days`、`stop_loss` 各上下档），L5 不会是空邻域。

### 4.7 常见报错对照（原文来自 `engine/config.py` 实跑）

| 写法 | 报错原文 | 改法 |
|---|---|---|
| `方向: above, 阈值: 5` | `buy[0].dir 必须是 above/below，得到 None` | 改英文 `dir`/`threshold` |
| `{op: ret_n, dir: above, threshold: 5}` | `buy[0]: 零件 ret_n 需要窗口参数 n` | 补 `n` |
| `n: 15` | `buy[0].n=15 不在窗口档位 [3, 5, 10, 20, 60, 120, 250]` | 取档位内窗口 |
| `{op: turn, n: 20, ...}` | `buy[0]: 零件 turn 不接受窗口参数` | 无窗零件删 `n` |
| `{op: xsec_pct}` | `factors[0]: 零件 xsec_pct 需要嵌套 of（基零件 spec）` | 补 `of` |
| `{op: xsec_pct, n: 20, of: ...}` | `factors[0]: 零件 xsec_pct 不接受窗口参数` | 删 `n` |
| `threshold: 4` | `buy[0].threshold=4.0 不在百分比档位 ±[1.0, 2.0, 3.0, 5.0, 8.0, 10.0, 15.0]` | 取档位值 |
| `close_over_ma_n ... threshold: 0.3` | `buy[0].threshold=0.3 不在倍数档位 [0.5, 0.8, 1.0, 1.2, 1.5, 2.0]` | 取倍数档 |
| `{op: pe_ttm, dir: above, threshold: 15}` | `buy[0]: 零件 pe_ttm 无阈值量纲，不能用作 buy/sell 条件（只能作打分因子 / rank）` | 改成 rank/factor |
| `holdings: 20` | `打分型 holdings 固定为 30（rules.md 第 4 节）` | 改 30 |
| `max_positions: 20` | `规则型 max_positions 固定为 10（rules.md 第 4 节）` | 改 10 或省略 |
| `max_hold_days: 30` | `max_hold_days=30 不在档位 [3, 5, 10, 20, 40, 60]` | 取档位值 |
| `rebalance: 周度` | `rebalance='周度' 不在 ['weekly_first_trade_day', 'monthly_first_trade_day']（周度 / 月度各取第一个交易日；rules.md 7.5）` | 用英文枚举 |
| `weight: 0` | `factors[0].weight 不能为 0` | 给非零权重 |
