### 3.3 打分型（`_parse_score_cfg` L221–255）

| 字段 | 必填 | 校验 / 档位 | 被拒写法（实测原文） |
|---|---|---|---|
| `factors` | ✅ | 非空列表，每项 `{op, n?, of?, weight}` | `打分型 factors 必须是非空列表` / `factors[0] 必须是 {op,n,weight} 形式` |
| `weight` | ✅ | 数值、**不能为 0**；**不受档位约束**（0.7、3.0、-2.0 均放行），权重和不必为 1 | `factors[0].weight 不能为 0`；`weight: '1.0'` → `必须是数值` |

### 3.4 条件 spec（`_parse_condition` L127–155）——**字段名是英文**

```yaml
buy:
  - {op: ret_n, n: 20, dir: above, threshold: 5}
```

| 键 | 必填 | 说明 |
|---|---|---|
| `op` | ✅ | 必须在 `OPERATORS` 里，否则 `未知零件 'xxx'（可用：[…41 个…]）` |
| `n` | 视 op | 只在 `has_window` 的 op 上允许，且只能是 **3/5/10/20/60/120/250** |
| `of` | 视 op | 只在 `ts_pct / xsec_pct / ind_rank` 上允许（且必填） |
| `dir` | ✅ | **只能是 `above` / `below`**（大小写不敏感） |
| `threshold` | ✅ | 按 `threshold_kind` 取档：`pct` → ±1/2/3/5/8/10/15；`mult` → 0.5/0.8/1.0/1.2/1.5/2.0；`streak` → 3/5/10/20/60/120/250；`none` → **该 op 不能作条件** |

**被拒写法实测（原文）**

| 写法 | 报错 |
|---|---|
| `{op: ret_n, n: 20, 方向: above, 阈值: 5}`（中文键） | `buy[0].dir 必须是 above/below，得到 None` ← 文档 docstring 里写的 `方向/阈值` 只是散文，**代码只认 `dir`/`threshold`** |
| `dir: gt` | `buy[0].dir 必须是 above/below，得到 'gt'` |
| 缺 `threshold` | `buy[0] 缺少 threshold` |
| `n: 7`（越档） | `buy[0].n=7 不在窗口档位 [3, 5, 10, 20, 60, 120, 250]` |
| `n: 3.9`（浮点） | **通过**，被 `int()` 截断为 3（宽松边界，写盘前请用整数） |
| `n: '20'`（字符串） | `buy[0].n 必须是数值，得到 '20'` |
| `ma_n` 缺 `n` | `零件 ma_n 需要窗口参数 n` |
| `turn` 带 `n: 20` | `零件 turn 不接受窗口参数` |
| `threshold: 4`（pct 越档） | `buy[0].threshold=4.0 不在百分比档位 ±[1.0, 2.0, 3.0, 5.0, 8.0, 10.0, 15.0]` |
| `threshold: -4` | 同上（负号只允许落在正档位上） |
| `close_over_ma_n` + `threshold: 1.1` | `不在倍数档位 [0.5, 0.8, 1.0, 1.2, 1.5, 2.0]` |
| `streak_up` + `threshold: 4` | `buy[0].threshold=4 不在整数档位 [3, 5, 10, 20, 60, 120, 250]` |
| `size_ln` 当 buy 条件 | `零件 size_ln 无阈值量纲，不能用作 buy/sell 条件（只能作打分因子 / rank）` |
| `threshold: true`（布尔） | `buy[0].threshold 必须是数值，得到 True` |
| `xsec_pct` 带 `n` | `零件 xsec_pct 不接受窗口参数` |
| `ts_pct` 缺 `n` | `零件 ts_pct 需要窗口参数 n` |
| `rank: {op: xsec_pct}`（缺 `of`） | `rank: 零件 xsec_pct 需要嵌套 of（基零件 spec）` |

**接受的宽松点**：`n` 可写浮点（截断）；`threshold` 写成整数值的浮点等价物均可；`stop_loss` 接受 `"无"/"none"/"5%"/"10.0%"`；嵌套可**任意深度**（实测 `ts_pct(n=20) of ts_pct(n=60) of pb`、`xsec_pct of xsec_pct of pb`、`ind_rank of xsec_pct of ps_ttm` 全部通过 config——`funnel` 只包一层，但 config 不限层数）。

## 4. 交叉判定：真实数据上**一定 0 成交**的 op

### 4.1 判定链（为什么"死列"= 0 成交）

1. 空表 → `prices.DataStore` 走 `align_by_ann_date` / `align_latest_by_trade_date` 后该列**整列 NaN**（`prices.py` L392–489）；`top_list` 空表时 `tl_on_list` 被写成**恒 0**（L472–473），不是 NaN。
2. 零件原样输出 NaN/0（`operators.py` 的 `_col()` 全 NaN；`top_list_n` 窗口最大值恒 0）。
3. 条件比较 `_cmp`：**NaN → False（不论 above/below）**（`backtest.py` L657–662）。
4. 规则型 `buy` 是 AND 语义，任一条件恒 False → 永不建仓 → **0 成交**。

### 4.2 实测对照（2014-01-01 ~ 2022-12-31，30 只股票，`max_hold_days: 20`）

| buy 条件 | 成交笔数 |
|---|---|
| `ret_n n=20 above 5`（活，对照组） | **1,680** |
| `ret_n n=20 below -1`（活，对照组） | **1,850** |
| `hk_ratio above 5` | **0** |
| `hk_ratio below 15`（极松方向也救不了） | **0** |
| `hk_chg_n n=20 above 1` | **0** |
| `inst_netbuy above 5` | **0** |
| `margin_ratio above 1` | **0** |
| `margin_chg_n n=20 above 1` | **0** |
| `fc_demean_ind above 5` | **0** |
| `top_list_n n=20 above 0.5`（恒 0，永不成立） | **0** |
| `top_list_n n=20 below 0.5`（恒 0 → 恒成立，退化） | **1,981**（买一切，非"0 成交"而是"无条件成交"） |
| `buy: [ret_n n=20 above 5, hk_ratio above 1]`（活+死 AND） | **0**（活条件被死条件废掉） |

结论：**16 个 op 在现有数据上必死**。上表除 2 行对照组与 1 行 `top_list_n below 0.5`（恒成立，反向退化）外，其余 9 行全部 0 成交；再叠加 8 个 `none` 量纲 op（`roe / or_yoy / netprofit_yoy / fc_type_code / fc_chg_mid / fc_days / ex_yoy / ex_days`，config 阶段就被拒作条件，作因子/rank 则退化）+ 注册零件 `ind_median_fc_chg_mid` = 16。

### 4.3 打分型不是"0 成交"，而是**退化按代码序选股**

- 全 NaN 因子 → `_winsorize_mad` → `_cross_rank` 对全 NaN 返回 **0.5 常数**（`backtest.py` L576–582）→ 总分 = 0.5×Σw 常数 → 排序退化为 `key=(-total, code)` → **按代码升序取前 N 只**。
- 实测：`factors:[{op: pb, weight:-1}]`、`[{op: roe, weight:1}]`、`[{op: hk_ratio, weight:1}]` 三份配置在同期都成交 114 笔；`roe` 与 `hk_ratio`（两个死因子）的首批买入**完全相同且严格按代码升序**（`sh.600000, 600004, 600006, 600008, 600009, 600011, 600015, 600016`），`pb` 的首批买入是 `sh.600019, 600026, 600029, …`（有真实排序）。
- 同理 `rank` 用死 op（`roe` / `hk_ratio`）：成交 1,680 笔但首批买入退化为代码序，与 `rank: size_ln` / `rank: ret_n` 的真实排序不同。
- **注意本数据只有 30 只股票而 `holdings` 固定 30**，所以打分型在"选中哪些股票"上本来就没有自由度（全选），退化只体现在**买入顺序**；换成 1,698 只全市场时，死因子会实打实选出"代码最小的 30 只"。

### 4.4 另一类"结构性 0 成交"（与数据无关，是阈值/量纲错配）

`0/1` 或 `0~1` 值域的 op 配 `mult` 档位里 >1 的阈值必然不成立：

| 写法 | 实测 |
|---|---|
| `close_pos_range above 1.2` | **0 笔**（取值 ≤1） |
| `close_pos_range above 0.8` | 1,923 笔 |
| `break_high_n / top_list_n / etf_above_ma_n` + `above: 1.0/1.2/1.5/2.0` | 结构性 0 笔（这三者只该用 `above 0.5`） |
| `top_list_n` 用 `below 0.5` | 恒成立（恒 0 < 0.5），等于无条件买入 |

## 5. 特别标注：市场级算子 与 factor pool 排除

### 5.1 "市场级"算子 = `etf_above_ma_n`（唯一一个）

| 项 | 内容 |
|---|---|
| 定义位置 | `engine/config.py` L44–48 `MARKET_LEVEL_OPS = frozenset({"etf_above_ma_n"})`；`funnel.py` L1044 同名同值（生成器侧） |
| 语义 | 在**单只 ETF 日线**上求值：`ETF_BENCHMARK = "510300.SH"`（`prices.py` L64），`close_adj = close × fund_adj`，当日复权收盘 > N 日均线 → 1 否则 0 |
| 被拒位置（实测） | `factors[0]`、`factors[0].of`（嵌套）、`rank` 三处都抛 `ConfigError`：`零件 etf_above_ma_n 是市场级零件（当日全市场同值），不能作打分因子 / 排序键 / 嵌套基零件；只能作 buy/sell 条件（rules.md 7.5）` |
| 允许位置 | `buy` / `sell` 条件（实测 `{op: etf_above_ma_n, n: 20, dir: above, threshold: 0.5}` → 1,642 笔成交；`n=250 below 0.5` → 984 笔） |
| 运行时第二道闸 | `backtest._op_values` 对它在股票面板上直接 `ValueError`（L738–741）；只能走 `_etf_values / _etf_value_on`（L752–766），读 `store.etfs[ETF_BENCHMARK]` |
| 为什么拒 | 截面秩恒并列 → 选股退化成按代码序取前 N（`config.py` L44–48 注释、`funnel.py` L1042–1043） |
| 数据现状 | 可用：510300 有 3,064 行 ETF 日线；另外 3 只 ETF（510500/518880/511010）有数据但**无任何算子使用** |

> 旁证：`buy` / `sell` 里不存在"把市场级零件藏进 `of`"的绕过路径——三个 wrapper（`ts_pct / xsec_pct / ind_rank`）都是 `threshold_kind="none"`，本身不能作条件，config 会先以 `零件 ts_pct 无阈值量纲，不能用作 buy/sell 条件` 拒掉（实测）。

### 5.2 被 factor pool 排除的 op

`engine/funnel.py` 的随机池（**不是** config 的硬校验，而是猴子生成器不抽）：

| 池 | 定义 | 被排除的 op | 排除理由 |
|---|---|---|---|
| `FACTOR_BASE_POOL`（L1045–1046） | `OPS_WITH_N + OPS_NO_ARG` 减去 `OF_WRAPPERS` 与 `MARKET_LEVEL_OPS` | **`ts_pct`、`xsec_pct`、`ind_rank`**（`OF_WRAPPERS`，L1035）+ **`etf_above_ma_n`**（市场级） | wrapper 只能作外层包 `of`；市场级作因子无截面离散度 |
| `OPS_CONDITION`（L996–997） | `threshold_kind != "none"` | **18 个 `none` 量纲 op**：`size_ln, pe_ttm, pb, ps_ttm, roe, or_yoy, netprofit_yoy, fc_type_code, fc_chg_mid, fc_days, ex_yoy, ex_days, ts_pct, xsec_pct, ind_rank, ind_median_pb, ind_median_ps, ind_median_fc_chg_mid` | 无量纲，不能作 buy/sell |

即：

| 口径 | 数量 | 说明 |
|---|---|---|
| 全部 op | 41 | 36 内置 + 5 注册 |
| 可进 `factors` / `rank` | **37** | 41 − 3 wrapper − 1 市场级；其中 16 个在现有数据上是死的（剩 **21 个可用**） |
| 可进 `buy` / `sell` | **23** | 41 − 18 个 `none` 量纲；其中 7 个在现有数据上是死的（`fc_demean_ind, top_list_n, inst_netbuy, margin_ratio, margin_chg_n, hk_ratio, hk_chg_n`）→ 剩 **16 个可用** |
| 现有数据上真正可用 | **25** | 24 个通用 + `etf_above_ma_n`（仅 buy/sell） |

用生成器实测确认的两条不变式（`funnel.py` L1007–1011 的 import 期 assert）：
`set(OPS_WITH_N) | set(OPS_NO_ARG) == set(OPERATORS)`、`set(OPS_CONDITION) == set(OPERATORS) - NO_THRESHOLD_OPS`。

## 7. 审计备注（风险点，供后续复核）

1. **写入配置前必过的三道闸**：`dir/threshold` 英文键 → 窗口/阈值档位 → `threshold_kind` 量纲。写中文 `方向/阈值` 会被判 `dir 必须是 above/below`，容易被误读成"零件不存在"。
2. **静默忽略的顶层字段**（`universe`、rule 里写 `holdings`、score 里写 `buy`）不会报错也不生效——配置文件"看起来对"不等于"真的被使用"。
3. **量纲陷阱**：`0/1`（`break_high_n`、`top_list_n`、`etf_above_ma_n`）与 `0~1`（`close_pos_range`、`ts_pct/xsec_pct/ind_rank`）用 `mult` >1 阈值一律结构性 0 成交；`top_list_n` 用 `below 0.5` 则恒成立，等于不要条件。
4. **死 op 不会在配置阶段报错**：`config.load_config` 对 `roe` / `hk_ratio` 等只查名字与量纲，不查数据是否有值（实测 `factors:[{op: roe}]`、`rank:{op: roe}` 全部 PASS）。筛选前应先用本报告的"0 成交清单"做黑名单。
5. **数据规模提醒**：现有 `data/raw/` 是 30 只股票的自检子集（`stock_basic`/`index_member_all` 各 30 行），`holdings: 30` 与 `max_positions: 10` 的筛选自由度被压缩；`is_st` 恒 0（`namechange` 空）意味着 ST 过滤在本数据上完全不生效；行业只有 14 个（证监会口径，非申万），`ind_rank` / `neut_industry` 的分组粒度显著粗于设计假设。
6. **`threshold_kind="none"` 的 18 个 op 不是"没用"**：它们只能作 `factors` / `rank` / 嵌套 `of` 基零件，`config` 拒绝的是把它们写成 buy/sell 条件。
